# AI 接口修复与验收

本轮只使用虚构花盆资料、独立测试账户和测试数据库。不读取真实书籍、命例或私有规则。

## 连接问题

在独立 Workerd 测试中复现：`redirect: 'error'` 在该运行环境抛出 TypeError，请求未发送，却被原错误处理显示为网络超时。改为 `manual`，任何 3xx 均拒绝处理，密钥不会随重定向发送到另一地址。个人接口与本站千问调用均修复。

无密钥测试已经收到百炼 HTTP 响应，证明修改后的运行环境能够发送请求。它不证明用户密钥、模型权限、余额或生产环境当次连接已经通过。真实用户密钥由用户在页面验证，不在开发对话中读取。

模型 ID 原本为文本输入框；本轮明确标注可手动修改，qwen-plus 只是默认值。

## 固定检索基线

运行 `node evaluations/run-retrieval.mjs`，结果保存在 `evaluations/baseline.json`。

- 12 道虚构题：9 道有相关依据，3 道无可见依据。
- 有依据题 Recall@5 和 MRR@5 均为 8/9（88.9%）。
- 简繁体、编号 120 与 240 的书页、跨书检索均找到预期选段。
- 无可见依据题均未召回，包括仅存在于限制访问的虚构书籍中的文字。
- “植物渴了该怎么办”仍未召回“给盆栽补水”的段落，保留为已知失败案例。

这不是完整 240 页 OCR 测试，不证明真实书库第 120 页已识别，也不是向量模型或实际回答质量评测。该基线只覆盖当前关键词和 BM25 检索。

## 用户可运行的模型验收

账户 → 我的 AI 接口 → 模型实际能力验收。成功验证并解锁接口后，可分别运行：原文问答、跨文献分歧、缺少依据。每次操作明确确认费用，只请求一次，不自动重试。服务端题目固定，不能替换为上传内容。

结果与人工评价按账户在本机加密保存。自动检查区分原文引用、关键词和拒答形式；这些检查不等于语义正确性，最终需人工核对。

## 研究结果衔接

研究 Agent 的结果可打开原页。转交前重新校验所有公开来源：普通账户可带入个人研究表单，核心账户还可带入技法草稿。转交只填写待核对表单，不自动保存、创建规则、审核或发布。技法仅带入原文与出处，不将 AI 结论冒充运算条件。研究保存后可继续使用已有分支、观察反馈及复盘功能。
