# 密码遗忘与重置

## 账户登录

登录框旁的“忘记登录密码？”直接打开原有的恢复码表单并带入用户名。恢复必须验证事先保存的恢复码；重置后旧密码、旧登录会话与恢复码失效。账户记录及权限不因重置而改变。

尚未设置恢复码时，不能只凭用户名取得账户。仍能登录的用户应在“账户安全”生成并保存恢复码。ChatGPT 登录使用原登录入口；本项目不重置 ChatGPT 密码。没有配置邮件发送或邮件身份验证，不显示虚假的邮件找回功能。

## 本机加密空间

本机书库、本机 AI 研究册和我的 AI 接口各有独立的“忘记密码 / 重置”入口。必须登录所属账户，书库还需核心权限；填写两次新密码并输入“重建加密空间”后才执行。

重置在单个 IndexedDB 事务中把原账户的当前密文移入归档，再建立新密码保护的空白空间。已有归档继续保留，其他账户和其他命名空间不受影响。事务失败则回滚，原空间保持不变。新密码无法解开旧资料；旧密码不被找回或展示。

“查看保留的旧密文”只显示重置日期。记起旧密码后，先用新密码解锁当前空间，再输入旧密码恢复，旧密文仍保留。API 配置恢复后重新选择使用；重置后的空白空间则需重新填写并验证 API 密钥。

归档仍在当前浏览器，清除网站数据或卸载时可能一并丢失，不是跨设备备份。密码与密文的重建、解密在本机进行，只有当前登录状态验证请求发给本站。旧标签页通过通知锁定；加密写入还检查当前头记录，拒绝重置前的旧密钥写入。

## 验证范围

只使用虚构账户及资料，未重置任何实际用户数据。

- 单元验证：错误确认、错误旧密码、账户切换、跨账户隔离、旧标签页写入拒绝、重复重置与归档恢复。
- 浏览器验证：三种空间的真实 IndexedDB 重置与恢复、必需的确认输入、登录找回入口；过程中没有发送本机密码的 POST 请求。
- 原有恢复码测试继续验证一次性使用、旧会话失效及错误恢复码拒绝。
